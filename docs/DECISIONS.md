## 本轮范围和结果

遵循 V4.0 第 10 节与 AGENTS.md 的空仓库规则，建立 FastAPI + Pydantic v2 最小服务、pytest 基础、Ruff 和 mypy。仅提供 `GET /api/v1/health`，不接 LLM、数据库、前端或经营公式。

开发依赖由 `backend/pyproject.toml` 声明、`backend/uv.lock` 锁定，解释器限定 Python 3.12。依赖包不全局安装。默认 uv 缓存路径不可写，使用 `/tmp/before-open-uv-cache`；跨文件系统使用 copy 模式，保留 TLS 与制品校验。

此处的“最小服务可运行”不等于产品闭环可用。完整业务仍未开发。

## 可行性及必要细化

| V4.0 方向 | 判断与采用方式 | 边界或需细化处 |
|---|---|---|
| 两类引擎、三种业务 | 可行；纯 Python 分支计算，Pydantic 判别联合 | 不拓展行业；不能把易损耗库存结转或把服务套成零售 |
| 金额确定性 | 采用人民币整数分，输入严格整数 | 不隐式接收 bool、float 或数字字符串；前端元转分须显式精确转换，阶段 1 不做前端 |
| SceneSpec 草案 | 保留字段包装与业务类型，补齐三类字段契约 | 草稿允许 null，执行输入要求计算所需字段完整；不把未知当 0 |
| 来源可信 | 保留六种 source 枚举、证据与派生依赖 | 合法枚举不代表来源真实；后续 API 按写入入口控制来源，Agent 无权自行升级为已核验 |
| 不可变版本与可重算 | 阶段 1 定义值对象与快照；阶段 2 落事务与持久化 | Pydantic frozen 不是数据库不可变保证；嵌套输入也不得原地修改 |
| 场景比较 | 记录输入差异、需求假设和比较期间 | 售价变化不推导销量；不同假设的结果不得称为同条件优劣 |
| 服务计算 | 取消数先校验不超过预约数，再套既定公式 | `max(0, booked-cancelled)` 不能用于掩盖非法输入；分钟应包含用户确认的拍摄及后期等时间 |
| 预算工具 | 零售按本轮预先付款计算缺口 | 服务未定义付款时点与预算字段，不把服务总成本擅自视为开业前付款；未知预算仅报告无法判断 |
| 单 Agent + 白名单 | 架构可行，阶段 4 接 LangChain/LangGraph | 原图约 12 个节点与“最多 8 节点/6 次调度”需定义计数单位；实现前明确每次确认间的执行段、重试计数和恢复幂等，不能静默调大限制 |
| 工作流恢复 | checkpointer 与业务数据库各司其职 | 中断恢复不得重复写业务版本；需要幂等键、事务与并发测试，不能只依赖聊天历史 |
| 前端轻松交互 | 秒哒优先，复用动态控件和后端契约 | 当前无前端，不能宣称秒哒已经接通；轮询优先，SSE 和复杂队列不预先引入 |
| 匿名跨域访问 | 技术上可行，阶段 2/3 联调验证 | 必须实测 Cookie、SameSite/Secure、CORS 白名单、CSRF 和项目所有权，随机项目 ID 不等于授权 |
| SQLite 开发可选 | 本轮不引入数据库 | 阶段 2 优先以 PostgreSQL 验证迁移、约束与并发；SQLite 测试不能替代生产语义 |

补充决定：固定成本按一次明确的模拟期间计入，三类结果明确简化边界；不自动添加税、退款、折旧、需求弹性。P0 仍保留三种类型，不因文档末尾的进度取舍建议自行缩减首版范围。
