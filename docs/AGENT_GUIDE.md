# 模型接入与 ScenarioAgent

## 页面使用

1. 按 QUICKSTART 启动数据库和前后端；更新旧版本后先运行 `uv sync --locked --no-install-project`、`uv run --no-sync alembic upgrade head`。当前迁移版本为 **0002**。
2. 点击顶部“模型接入”，选择 DeepSeek、OpenAI 或通义千问，以及后端白名单列出的候选模型。
3. 填写自己的 API Key，阅读暂存和费用说明，勾选授权后连接。此步只暂存连接信息，不向服务商发送模型请求，也不证明额度或模型可用。
4. 在首页保存一句话想法，进入准备页后点“让智能体准备场景”。只有这类主动操作才实际调用模型。
5. 检查已知事实与最多3个问题。填写答案，或明确选择演示假设继续。已有确认方案中的数值不会被重新抽取的原句覆盖。
6. 检查完整草稿，点击“确认这些条件并运行分析”。此时才保存版本、选择并执行工具。
7. 查看风险卡和“真实执行记录”。建议修改备货时，需再次点击确认，系统创建独立子方案并运行比较，不覆盖父版本。

也可以继续手动预演；在沙盒中点“分析当前已保存方案”，或在现实挑战中请求一张可编辑任务草稿。任务仍需检查后手动保存；模型不会替你开展调查或伪造观察。

## 密钥、服务与费用

- 支持的固定服务地址：api.deepseek.com、api.openai.com、dashscope.aliyuncs.com。用户输入不能指定任意 URL 或任意模型名。候选模型可用性仍需用实际服务权限验证。
- 普通用户的 Key 由接入表单经后端使用，不嵌入前端 bundle、不写 localStorage/sessionStorage、不进业务库、checkpoint 或工具日志。服务进程内按匿名会话暂存，30分钟有效；超时不可使用并在访问时清理，断开会移除连接。不是长期保险库。
- 公网提交 Key 必须 HTTPS；只为本机回环开发与隔离测试保留 HTTP 例外。不要把 Key 发到聊天。建议使用可限额、可撤销的专用 Key。
- 刚填写后显示“尚未验证”。只有实际结构化模型请求完成后才标记曾调用成功；连接可达不代表场景事实经过现实核验。
- 每段最多8个执行节点、6次模型/工具调度；单个模型操作最多尝试2次、每次最多1600个输出 token，SDK 自动重试关闭。它们限制调用量，**不是金额封顶**；实际计费以服务商规则为准。
- 运行中的用户 Key 不跨服务重启保留；当前内存连接适用于单进程原型，多实例生产部署需另行设计受控密钥服务或会话粘连。
- 管理员可用 BO_LLM_* 注入明确授权的服务器默认模型，默认 BO_LLM_ENABLED=false。应用不自动加载 .env，禁止把服务器 Key 配为 VITE_*。
- LangSmith 外部追踪显式关闭。不会抓取市场数据，也不会自动把网络价格或用户观察升级成第三方核验。

## 当前云环境所需条件

本轮未提供真实模型 Key，也未发送真实计费请求。无凭据的只读连接诊断显示模型服务被代理 403 阻止；已准备对应三个域名的环境网络草稿。需要在环境设置审阅、保存并发布相关配置，才能激活允许规则。草稿保存不等于当前网络已改变。

若在自己的电脑运行，使用自己正常可达的服务、有效模型和额度，在页面接入后验证即可。模型失败会保留已保存方案和手动路径，不伪造完成状态。

## API 补充

所有接口沿用匿名所有权和 request_id。POST 需要 CSRF；工作流 POST 还需要 Idempotency-Key。完整类型见自动生成 OpenAPI。

| 接口 | 用途 |
|---|---|
| GET /api/v1/models | 当前匿名会话的连接状态、候选模型；不返回 Key |
| POST /api/v1/model-connection | 暂存用户授权的连接，不验证/计费；不写入幂等缓存 |
| POST /api/v1/model-connection/disconnect | 移除当前会话的临时连接 |
| POST /api/v1/projects/{id}/scene-draft | 抽取有原句证据的事实，生成待确认草稿 |
| POST /api/v1/projects/{id}/clarifications | 只补未知数值或明确使用演示条件，不覆盖已有值 |
| POST /api/v1/projects/{id}/agent-confirm | 必须 confirmed=true；冻结版本、规划工具并运行 |
| POST /api/v1/projects/{id}/agent-runs | 对已保存、属于当前项目的版本进行分析 |
| GET /api/v1/projects/{id}/agent-runs/{run_id} | 实际状态、来源、风险、工具及模型调用摘要 |
| POST /api/v1/projects/{id}/agent-runs/{run_id}/actions | 只接受本次分析已给出的、用户确认的建议 |
| POST /api/v1/projects/{id}/agent-retry | 用户明确重新确认后重试失败执行 |
| POST /api/v1/projects/{id}/experiment-draft | 任务草稿，不自动保存实验或记录观察 |

缺少模型连接时返回一个诚实的 failed 执行记录，error_code=LLM_UNAVAILABLE、真实调用数为0。密钥失败、超时、限流、来源不受原句支持和调用限额均有稳定失败码；不将服务商异常正文或授权头返回用户。

## 工作流、事实与存储

一个 ScenarioAgent，LangGraph 节点负责抽取、准备、确认、保存、规划、执行、风险复核、等待选择和应用选择。LLM 只产出有限 Schema（事实引用/工具名/任务草稿），没有 shell、SQL、任意 URL 或代码执行工具。

阶段0记录的“长流程超过8节点”采用明确分段：**一次 HTTP 用户交互之间的一段**独立限额。首次抽取到确认中断为3个节点；恢复确认到工具与下一选择中断为6个节点；明确接受建议后为2个节点。累计节点/调用另行记录，不把内部框架调度当作额外模型额度。

抽取数值必须有原句连续短引文、唯一数字与匹配单位；金额按 Decimal 转整数分，未知值不补均价。原始事实、已确认方案和后续用户输入分别保留来源。数字算不清或证据不符时失败降级，不把模型输出当作计算结果。

LangGraph 的 agent_checkpoints / agent_checkpoint_writes 只存恢复状态，与 SceneVersion、SimulationRun、Observation 等业务事实分表。自定义事务 checkpointer 与业务写入共用数据库事务，并串行保护共享 Session，避免确认或工具失败留下半成品版本。服务重启后同一匿名身份、同一服务商模型可重新连接并恢复；密钥不会从 checkpoint 恢复。

工具日志包括真实名称、实际 request_id、版本、输入/输出摘要、状态和测得的持续时间。失败事务的工具标为 rolled_back，输出与临时版本引用清除；不把已回滚执行冒充业务成功。UI 最多展示3张风险卡；每张依据现有公式结果，改参数必须人工确认。

## 验证边界

自动化测试通过脚本化模型传输注入验证 Schema、工作流、确认、权限、失败、恢复与真实计算工具。该模型只存在 tests 中，生产 app.main 没有测试模式开关。浏览器脚本 --agent 的测试入口还要求显式隔离测试标记。

脚本化模型的通过不代表真实模型准确率、服务商可用性或实际市场预测。真实服务商的三条演示提示、费用和延迟仍需在有效授权/密钥/网络下记录。后续阶段6的真实模型评估与用户测试不在本轮冒充完成。
